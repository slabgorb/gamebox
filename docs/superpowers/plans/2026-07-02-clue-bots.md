# Clue Bots — Knowledge Tracker + Capped Shortlist + Persona Pick + Auto-Refute — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Clue AI opponent — a **deterministic knowledge tracker** (never misdeduces) feeding a **bounded, difficulty-capped shortlist**, chosen by a **persona (LLM) pick + banter**, plus **deterministic bot auto-refute** (least-leak card), plus the **six suspect personas** as `games:[clue]` catalog YAMLs — to the headless Clue engine shipped in E6-1/E6-2/E6-3.

**Architecture:** Pure ES-module functions under `plugins/clue/server/ai/` (+ one extension to `plugins/clue/server/rules/refute.js`), mapping 1:1 onto the established `chooseAction` contract used by words / backgammon / sorry. The bot is **stateless**: every layer is a pure function of the server `state` (its own hand, its own private ledger, and the public log) — no per-bot persistence, rebuilt each call, exactly like the other adapters. The tracker reads **only** the bot's own private information plus public data; it never touches `state.envelope` or another seat's `hands`/`ledgers` (that is the "never cheats / never misdeduces" guarantee). The die value is **never** produced by the bot (dice-are-client-side doctrine): the roll is a **values-less intent**, mirroring backgammon's `chooseAction`.

**Tech Stack:** Node ≥20, ESM, `node --test` + `node:assert/strict`. Reuses E6-1/E6-2/E6-3 modules (`cards.js`, `state.js`, `actions.js`, `view.js`, `geometry.js`, `rules/movement.js`, `rules/refute.js`) and the platform AI errors (`src/server/ai/errors.js`). No new dependencies.

## Global Constraints

- **Node ≥20, ESM** (`"type": "module"`); all imports use explicit `.js` extensions.
- **Tests:** `node --test` with `node:test` + `node:assert/strict`; test files live at repo root `test/clue-*.test.js` (flat dir, matching `test/risk-*.test.js`). Persona-catalog assertions may extend the existing catalog test rather than adding a new file.
- **`chooseAction` contract (exact — mirror words/backgammon/sorry):**
  - `async chooseAction({ llm, persona, sessionId, state, botPlayerIdx, userMessages = [] }) → { action, banter, sessionId } | { action, usedLlm: false }`.
  - Shortlist entries are `{ id, slot, action, summary }` (words' shape).
  - Parse LLM output with a local `parseLlmResponse(text) → { moveId, banter }`; on parse failure `throw new InvalidLlmResponse(...)`; on an id not in the shortlist `throw new InvalidLlmMove(parsed.moveId, shortlist.map(m => m.id))`. Both imported from `../../../../src/server/ai/errors.js` and re-exported (backgammon precedent).
  - Resume-aware system prompt: `systemPrompt: sessionId ? null : persona.systemPrompt` on the `llm.send({ prompt, sessionId, systemPrompt })` call.
  - A **no-decision** step (bot auto-refute; a single-option menu) returns **without** an LLM play call and sets `usedLlm: false` so the orchestrator does not burn a resume slot (sorry/cribbage precedent).
- **Dice are client-side, never a bot decision** (`docs`/project doctrine + `test/no-server-dice-rng.test.js`): the bot **never** materialises a die value and **never** contains `Math.floor(rng() * 6)`. When the bot elects to roll, `chooseAction` returns a **values-less** `{ type: 'roll' }` intent (backgammon precedent — "chooseAction returns a values-less roll intent"). The die value is supplied by the client and applied to the engine as the shipped `roll { value }` action (E6-3). The server never RNGs the die.
- **The bot goes through the reducers.** The orchestrator applies the bot's returned `action` via `adapter.plugin.applyAction(...)` — the bot never writes `state` directly. Every action the shortlist emits is a **shipped E6-1/E6-2/E6-3 action** (`roll`/`move`/`secretPassage`/`suggest`/`refute`/`accuse`/`pass`). The bot **never** emits the raw `enterRoom` action (see Delivery Finding F7).
- **Card ids** are the E6-1 catalog lowercase strings (`scarlett … plum`, `candlestick … wrench`, `kitchen … study`). **Room ids** in movement match the geometry catalog. **Persona ids** are hyphenated theme names (below) and are deliberately distinct from card ids.
- **Seat-indexed:** the bot's seat is `botPlayerIdx` (the orchestrator computes it from `state.seats.indexOf(botUserId)`). Read own hand as `state.hands[botPlayerIdx]`, own ledger as `state.ledgers[botPlayerIdx]`.
- **Geometry injection:** any function that needs the board takes `geo = BOARD` (default), matching E6-3, so movement/shortlist logic unit-tests against a synthetic mini-board.

## Bot architecture overview

Three layers map 1:1 onto `chooseAction`, plus a deterministic refute short-circuit:

```
chooseAction({ llm, persona, state, botPlayerIdx, sessionId, userMessages })
   │
   ├─ phase 'refute' & activeUserId is this bot  ──▶  chooseRefuteCard() [DETERMINISTIC, no LLM]
   │                                                  return { action:{type:'refute',payload:{card}}, usedLlm:false }
   │
   └─ otherwise (decision phases):
        tracker  = buildTracker({ state, seat })                 // layer 1 — never misdeduces
        shortlist = buildClueShortlist({ state, geo, seat,       // layer 2 — bounded, capped, diverse
                                         tracker, difficulty })
        if shortlist has exactly one entry ──▶ play it, banter-only call (usedLlm accounting normal)
        prompt   = buildTurnPrompt({ state, shortlist, seat, tracker, userMessages })   // layer 3 — persona
        parsed   = parseLlmResponse(llm.send(...))               //   pick by id + banter
        match    = shortlist.find(id === parsed.moveId)          //   validate → InvalidLlmMove
        return { action: match.action, banter: parsed.banter, sessionId }
```

**Layer 1 — knowledge tracker (`knowledge.js`, deterministic).** A card × location possibility matrix (locations = the N seats **plus** `'envelope'`), seeded from three sources — the bot's own hand, the bot's own private ledger, and the public log (`no-refute` ⇒ that seat holds none of the three; `refute` ⇒ that seat holds ≥1 of the three, tracked as a clause) — then run to fixpoint with standard Clue constraint propagation (single-possible-location pinning, hand-size saturation, category elimination, single-clause resolution). Pure bookkeeping; the **"never misdeduce"** guarantee. Reads **only** the bot's own private info + public data; **never** `state.envelope` or other seats' `hands`/`ledgers`.

**Layer 2 — capped shortlist (`shortlist.js`, deterministic, with a difficulty knob).** A bounded, diverse menu keyed off the current sub-state (top-of-turn / post-roll movement / suggest / accuse-or-pass), reusing the words `POINTS_CAP` + backgammon `MAX_SHORTLIST` idiom: module-level caps with tuning comments, and a fallback to a non-empty menu if a cap ever empties it. Imperfection is a **designed property of the menu**, not LLM incompetence.

**Layer 3 — persona pick + banter (`clue-player.js` + `prompts.js`, LLM).** The persona chooses one shortlisted action **by id** and returns banter; style is *which* reasonable slot it picks. Identical parse/validate path to words/backgammon.

**Auto-refute (`rules/refute.js` + `clue-player.js`, deterministic).** When the bot is the refuter, it reveals the **least-leak** matching card instantly, with no LLM call — the invisible-mechanic-server-side half of the dice/refute doctrine.

**Six personas.** In Clue you play as a suspect, so the six suspects are the six personas: `games:[clue]` catalog YAMLs whose `color` aligns to the canonical pawn colour; portraits auto-load by persona id.

## Task 1: Knowledge tracker (`knowledge.js`) — deterministic, never misdeduces

**Files:**
- Create: `plugins/clue/server/ai/knowledge.js`
- Test: `test/clue-knowledge.test.js`

**Interfaces:**
- Consumes: `SUSPECTS`, `WEAPONS`, `ROOMS`, `ALL_CARDS`, `categoryOf` from `../cards.js`; reads only `state.seats`, `state.hands[seat]` (own), `state.ledgers[seat]` (own), `state.log`. **Must not read** `state.envelope`, `state.hands[other]`, or `state.ledgers[other]`.
- Produces: `buildTracker({ state, seat }) → tracker` (shape above).

**Fact sources (seed the matrix):**
1. **Own hand** (`state.hands[seat]`): each held card ⇒ `holderOf(card) = seat`; not envelope; not any other seat.
2. **Own ledger** (`state.ledgers[seat]` = `[{fromSeat, card}]`): each entry ⇒ `holderOf(card) = fromSeat`; not envelope.
3. **Public log episodes** (parse `state.log` into suggestion episodes — a `suggest` entry, then its `no-refute` passes, then an optional terminal `refute`):
   - `{type:'no-refute', seat:P}` for suggestion `{A,B,C}` ⇒ P holds none of A,B,C (mark `not-P` for each).
   - `{type:'refute', bySeat:P, ofSeat:Q}` for `{A,B,C}` ⇒ **clause** "P holds ≥1 of {A,B,C}". (If the bot is Q, the exact card is already in its ledger — the clause is redundant but harmless.)

**Propagation to fixpoint** (repeat until no change):
- **Single-location pin:** if a card's only remaining possible location is L, set `holderOf(card)=L`.
- **Hand saturation:** if a seat's proven-held count equals its hand size (hand sizes are derivable: 18 dealt round-robin over N seats), every other card is `not-that-seat`.
- **Category elimination:** if 5 of a category's 6 cards (rooms: 8 of 9) are located in seats (not envelope), the remaining card is the envelope card for that category.
- **Envelope uniqueness:** a card pinned to `'envelope'` is `not` in any seat; and its category's other cards are `not-envelope`.
- **Single-clause resolution:** if all but one card of a clause `{P, [A,B,C]}` are already `not-P`, then P holds the surviving card (pin); drop the clause.

## Task 2: Least-leak bot refute (`rules/refute.js` extension)

**Files:**
- Modify: `plugins/clue/server/rules/refute.js` (add `chooseRefuteCard`; leave `findRefuterWalk` untouched)
- Test: `test/clue-refute-choice.test.js`

**Interfaces:**
- Consumes: `state.hands[refuterSeat]`, the in-flight `state.suggestion` (`{ suspect, weapon, room, bySeat }`), and `state.log` (to score "already-shown" leakage).
- Produces: `chooseRefuteCard(state, refuterSeat, named) → cardId`. `named` defaults to `{suspect,weapon,room}` from `state.suggestion`. Returns exactly one card the refuter **holds** that is among the three named. **Deterministic** (a stable tie-break — never `Math.random`).

**Least-leak policy** (design §6): among the refuter's held matching cards, prefer the card that leaks the least *new* information to the suggester:
1. Prefer a card the refuter has **already shown this suggester** before (visible in the suggester-directed history) — re-showing leaks nothing new.
2. Else prefer a card the suggester most likely already holds/has seen (heuristic: a card named in one of the suggester's own prior suggestions is a weak signal; keep this conservative and deterministic).
3. Tie-break by a fixed order (`ALL_CARDS` index) so the choice is reproducible.

> Note: the refuter's private view of "what the suggester has seen" is limited to public signals + its own shows. Keep the heuristic simple and **deterministic**; correctness (must be a held, named card) matters more than optimality.

## Task 5: `chooseAction` — persona pick, banter, auto-refute short-circuit (`clue-player.js`)

**Files:**
- Create: `plugins/clue/server/ai/clue-player.js`
- Test: `test/clue-ai-player.test.js`

**Interfaces:**
- Consumes: `buildTracker` (Task 1), `buildClueShortlist` (Task 3), `chooseRefuteCard` (Task 2), `buildTurnPrompt`/`parseLlmResponse` (Task 4); `InvalidLlmResponse`/`InvalidLlmMove` from `../../../../src/server/ai/errors.js` (re-export them, backgammon precedent).
- Produces: `async chooseAction({ llm, persona, sessionId, state, botPlayerIdx, userMessages = [], geo = BOARD }) → { action, banter, sessionId } | { action, usedLlm:false }`.

**Control flow:**
1. `seat = botPlayerIdx`.
2. **Refute short-circuit (deterministic, no LLM):** if `state.phase === 'refute' && state.activeUserId === state.seats[seat]`, return `{ action: { type:'refute', payload:{ card: chooseRefuteCard(state, seat) } }, usedLlm:false }`. (Mirrors sorry's forced-move / cribbage single-card short-circuit; no resume slot burned.)
3. Otherwise build `tracker` + `shortlist`.
4. **Single-option short-circuit:** if `shortlist.length === 1`, play it. Spend a **banter-only** call (no move menu) so the bot still chirps and the orchestrator's resume-slot accounting stays normal (sorry precedent) — or return the action with an empty banter if no banter call is warranted. Do **not** set `usedLlm:false` if a banter call was made.
5. Build the prompt, `llm.send({ prompt, sessionId, systemPrompt: sessionId ? null : persona.systemPrompt })`.
6. `parseLlmResponse` → on failure `throw new InvalidLlmResponse(e.message)`.
7. `match = shortlist.find(m => m.id === parsed.moveId)`; if none `throw new InvalidLlmMove(parsed.moveId, shortlist.map(m => m.id))`.
8. Return `{ action: match.action, banter: parsed.banter, sessionId: r.sessionId }`.

**No dice RNG:** `chooseAction` (and `shortlist.js`) contain **no** `Math.floor(rng()*6)` and never materialise a die value; the roll branch returns the values-less intent unchanged from the shortlist.
