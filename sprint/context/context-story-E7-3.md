## Title
Pawn move reverts after page refresh (move not persisted like the suggestion log)

## Problem
Playtest bug: mid-game the human (playing Scarlett) moved to the conservatory, then refreshed the page — the pawn was back at its pre-move position, i.e. the move reverted. The suggestion history was intact, so this is NOT total state loss: the pawn-location update from a move is not persisted the same way the suggestion log is. Likely a Clue state-serialization / rehydration gap — either the persisted game-state row is not written after a 'move' action, or cluePublicView rebuilds pawn location from stale persisted data on reload. Investigate: how POST /api/games/:id/action persists state after a 'move' vs a 'suggest' (src/server/routes.js action route, src/server/games.js + db.js state write), the clue move apply (plugins/clue/server), and the persisted-state -> cluePublicView rehydration. Use systematic-debugging: reproduce (move, refresh, observe revert), locate the divergence between persisted and in-memory pawn state, then fix so a move survives reload.
